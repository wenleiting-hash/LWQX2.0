# 查券结果弹窗化改造方案与计划

## 一、 背景与目标
为了缩短用户的决策和操作路径，提升查券转化率，现计划将查券结果的呈现方式从“**跳转至详情页**”改为“**当前页弹窗提示**”。同时，为确保小程序符合《微信审核规则》，所有引导文案必须做到客观、真实，杜绝夸大性词汇（如“免费领”、“发红包”、“必中”等）。

---

## 二、 核心逻辑与业务流转

### 1. 剪贴板识别与查券触发
- 当用户复制商品链接并打开小程序时，系统自动检测剪贴板内容，弹出拦截提示框：“检测到商品链接，是否立即查券？”
- **点击【立即查券】**：直接触发后端接口调用，并在当前页弹出查券结果弹窗。
- **点击【取消/反之】**：将该商品链接自动填入首页的搜索输入框中，等待用户手动点击搜索。

### 2. 接口调用策略（直调转链API）
不再针对链接类查询使用普通的“全网搜索”或“商品详情”接口，而是**根据平台特征直接调用对应的转链API**，一次性完成“查券+生成专属推广口令/链接”。

- **如果是淘宝链接**：
  - 调用：`批量高佣转链API（淘口令）接口` (`10001/api/open_gaoyongzhuanlian_tkl_piliang.ashx`)
  - **判断有无优惠券**：根据返回字段 `is_youquan`，若等于 `"1"` 则代表有优惠券；反之无券。
  
- **如果是京东链接**：
  - 调用：`京东转链API-新（自动匹配官方优惠券）` (`20000/api/open_jing_union_open_promotion_byunionid_get.ashx`)
  - **判断有无优惠券**：根据返回字段 `quanhou_jiage` 和 `size` 的对比，若 `quanhou_jiage < size` 则代表有优惠；反之无券。

---

## 三、 弹窗场景与合规文案设计

根据上述接口调用的判定结果，在首页弹出对应的结果 Modal 弹窗：

### 场景 1：查到商品，但没有优惠券 (无券)
- **判定条件**：调用转链 API 成功，但判定为无券（淘宝 `is_youquan != "1"` 或 京东 `quanhou_jiage >= size`）。
- **弹窗展示**：
  - **提示文案**：“暂时未查到优惠券，可复制专属口令，打开淘宝或京东app、京东小程序下单购买。”
  - **按钮动作**：
    - 针对淘宝：【复制口令，打开淘宝购买】
    - 针对京东：【打开京东小程序购买】 和 【复制链接，打开京东App】

### 场景 2：查到淘宝优惠券 (淘宝有券)
- **判定条件**：淘宝转链 API 成功，且 `is_youquan == "1"`。
- **弹窗展示**：
  - **提示文案**：“为您查到专属优惠券 ￥{金额}。口令已生成，请复制后打开淘宝下单。” *(合规点：直接说明金额，不使用“领红包”等诱导词汇)*
  - **按钮动作**：【复制专属口令，打开淘宝】

### 场景 3：查到京东优惠券 (京东有券)
- **判定条件**：京东转链 API 成功，且 `quanhou_jiage < size`。
- **弹窗展示**：
  - **提示文案**：“为您查到专属优惠券 ￥{金额}。请选择直接打开京东小程序，或复制口令打开京东App下单。”
  - **按钮动作**：
    - 主按钮：【跳转京东小程序领券】
    - 次按钮：【复制口令，打开京东App】

## 四、 具体技术改造计划 (Task Breakdown)

### Phase 1: 云函数重构 (`cf-coupon-search`)
- 修改现有的 `cf-coupon-search` 逻辑：如果 `query_type === 'url' || query_type === 'tkl'`，则不再调用 `api_quanwang`。
- 直接根据平台（淘宝或京东），调用对应的转链 API (`open_gaoyongzhuanlian_tkl_piliang` 或 `open_jing_union_open_promotion_byunionid_get`)。
- 在云函数中计算并透传出 `is_youquan` 或通过计算比对出 `hasCoupon` 的布尔值，统一返回给前端。

### Phase 2: 首页逻辑与 UI 重构 (`pages/index`)
- 完善剪贴板自动识别的弹窗流转逻辑，确保选择“取消”时将内容填入搜索框。
- 移除跳转 `/pages/detail/detail` 的 `wx.navigateTo`。
- 在首页新增一个全屏或居中的遮罩弹窗组件 `<view class="result-modal">`。
- 根据 `platform` 和是否含有优惠券，动态渲染上述合规文案与相应的跳转按钮。
- 将京东的 `wx.navigateToMiniProgram` 和淘宝的 `wx.setClipboardData` 事件绑定至弹窗按钮。

### Phase 3: 收尾与验证
- 在首页补充原先存在于 `detail.js` 中的历史足迹（footprints）保存逻辑。
- 依据《微信审核规则》进行合规测试复查。
