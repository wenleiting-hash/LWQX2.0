## 1.1 问题陈述 (Problem)

### 谁有这个问题？
所有在淘宝/京东看中商品后，想知道"有没有隐藏优惠券"的用户。

### 有多痛？
- 用户在淘宝看中一件 189 元的商品，但不知道是否存在 100 元的内部隐藏券。
- 传统方式需要：打开返利 APP → 注册登录 → 搜索商品名 → 翻找结果。整个流程 > 2 分钟，且大量用户在"注册"环节流失。
- 小栗鼠的解法：复制商品链接 → 打开小程序 → 自动弹出优惠信息。整个流程 < 5 秒，零注册。

### 不做会怎样？
产品失去核心价值主张。用户没有理由打开小栗鼠。

## 1.2 成功指标 (Success Criteria)

| 指标 | 定义 | 目标值 |
| :--- | :--- | :---: |
| 剪贴板触发率 | 有剪贴板内容被成功识别的 Session 占总 Session 比例 | ≥ 60% |
| 手动搜索使用率 | 通过搜索框手动输入/粘贴进行查询的 Session 占比 | ≥ 30% |
| 搜索结果点击率 | 搜索出结果后，用户点击进入详情页的比例 | ≥ 40% |
| 页面加载耗时 | 从发起查询到结果完整渲染完成的时间 | ≤ 3 秒 |

## 1.3 用户旅程 (User Journey)

### 场景 A：剪贴板自动识别流程（主流程 · 占预估 70% 流量）

```
1. 用户在淘宝 APP 看中商品，点击"分享" → 选择"复制链接"
   → 剪贴板中写入淘口令（如 "￥aBcDe￥"）或商品链接

2. 用户切换至微信，打开"小栗鼠"小程序
   → 小程序 onShow 生命周期触发剪贴板读取

3. 系统静默调用 wx.getClipboardData()
   → 正则匹配检测到淘口令格式 或 京东短链格式
   → 弹出半屏浮层确认框：
     ┌──────────────────────────────┐
     │  🔍 检测到商品链接            │
     │                              │
     │  "￥aBcDe￥"                 │
     │                              │
     │  [立即查券]    [忽略]         │
     └──────────────────────────────┘

4. 用户点击 [立即查券]
   → 调用云函数 cf-coupon-search（传入淘口令/链接）
   → 展示 loading 骨架屏（与详情页布局一致的灰色占位块）

5a. 查询成功：跳转至商品详情页（PRD-02）
5b. 查询失败/无券：展示 Empty State（见 1.5 边界处理）
```

### 场景 B：手动粘贴搜索流程（备用流程 · 占预估 30% 流量）

```
1. 用户打开小栗鼠，但剪贴板中无有效内容（或用户点击了"忽略"）
   → 不弹出浮层，展示默认首页

2. 用户看到屏幕中央的巨型搜索输入框
   → placeholder 文案："粘贴商品链接，一键查隐藏券"
   → 搜索框下方有 3 步引导动图（首次访问时展示）

3. 用户手动粘贴链接或输入商品关键词到搜索框
   → 点击搜索按钮或键盘确认键

4a. 输入为淘口令/京东短链：直接走转链查询，同场景 A 第 4 步
4b. 输入为关键词文本：调用云函数 cf-coupon-search（query_type=keyword）
   → 展示搜索结果列表（商品卡片列表，规格见 REQ-0105）
   → 用户点击任意卡片 → 跳转详情页（PRD-02）
```

## 1.4 功能需求与验收标准 (Requirements)

### REQ-0101 巨型搜索输入框

**描述：** 查券页面的核心交互组件。位于页面视觉中心偏上位置，是用户手动查券的唯一入口。

**验收标准：**
- Given 用户首次打开查券 Tab，When 页面渲染完成，Then 搜索框位于屏幕垂直方向 30%-40% 的位置，宽度占屏幕 90%，高度不低于 44px
- Given 搜索框处于空状态，When 用户未聚焦，Then 展示 placeholder 文案"粘贴商品链接，一键查隐藏券"
- Given 用户点击搜索框，When 获得焦点，Then 自动弹出键盘，placeholder 文案消失
- Given 用户已输入内容，When 点击搜索按钮或键盘确认键，Then 触发搜索请求
- Given 用户已输入内容，When 点击输入框右侧的清除按钮(×)，Then 清空输入内容并保持焦点
- Given 搜索请求已发起，When 等待响应中，Then 搜索按钮变为 loading 状态，禁止重复提交

### REQ-0102 剪贴板智能探针

**描述：** 在小程序每次从后台切回前台（onShow）时，静默读取剪贴板内容，识别是否包含淘口令或京东链接。

**验收标准：**
- Given 用户剪贴板中包含淘口令（正则：`/￥[a-zA-Z0-9]{6,}￥/`），When 小程序触发 onShow，Then 弹出半屏确认浮层，展示识别到的内容
- Given 用户剪贴板中包含京东链接（正则：`/https?:\/\/(u\.jd\.com|m\.jd\.com|item\.jd\.com|jd\.com)\/[a-zA-Z0-9\/\?\=\&]+/`），When 小程序触发 onShow，Then 弹出半屏确认浮层
- Given 用户剪贴板中包含淘宝商品长链接（正则：含 `taobao.com` 或 `tmall.com` 或 `tb.cn`），When 小程序触发 onShow，Then 弹出半屏确认浮层
- Given 本次 Session 内用户已关闭过确认浮层，When 再次 onShow 且剪贴板内容未变化，Then **不再弹出**（微信合规 5.16 防过度营销）
- Given 本次 Session 内剪贴板内容发生变化（新的淘口令），When 再次 onShow，Then 允许再次弹出
- Given 用户未授权剪贴板权限（wx.getClipboardData 失败），When 小程序 onShow，Then 不弹出浮层，搜索框展示脉冲高亮动效提示手动粘贴
- Given 剪贴板中不包含任何可识别格式，When 小程序 onShow，Then 不弹出浮层，搜索框正常展示

**数据流规格：**
```
[onShow 触发]
    ↓
[wx.getClipboardData()]
    ↓ 成功
[正则匹配：淘口令 / 京东短链 / 淘宝长链接]
    ↓ 匹配成功
[检查 Session 防重标记]
    ↓ 未标记过 或 内容已变化
[弹出确认浮层]
    ├── 用户点击 [立即查券] → 调用云函数转链 → 跳转详情页
    └── 用户点击 [忽略] → 关闭浮层，设置 Session 防重标记
```

### REQ-0103 实时查券成功弹幕组件

**描述：** 在搜索框上方区域展示滚动播报条，展示其他用户查券成功并省钱的真实事件流，通过社会认同感（Social Proof）刺激当前用户使用查券功能。

**数据源（分阶段）：**

| 阶段 | 数据源 | 说明 |
| :--- | :--- | :--- |
| Phase 1.0 MVP | **真实事件 + B端种子数据混合** | 云函数 `cf-coupon-search` 每次查券成功时，写一条脱敏记录到云数据库 `bulletin_logs` 集合；B端后台可手动录入种子弹幕作为冷启动兜底 |
| Phase 1.5 | **纯真实事件流** | 用户量起来后关闭种子数据，全部切换为真实查券成功事件 |

**云数据库 `bulletin_logs` 集合结构：**
```json
{
  "nickname_masked": "省钱达人",        // 脱敏昵称（随机从预设池中选取，如"小*鼠用户""精打细算""羊毛党"）
  "saved_amount": 56,              // 实际省钱金额 = 原价 - 券后价
  "product_title": "夏季冰丝T恤",  // 商品标题（仅取前6字）
  "timestamp": 1713600000000,       // 事件时间
  "source": "real"                  // "real"=真实事件 / "seed"=种子数据
}
```

**验收标准：**
- Given 查券页加载完成，When 用户可见搜索框区域，Then 搜索框上方展示一条向上滑入的弹幕播报
- Given 弹幕列表中有多条数据，When 当前弹幕展示 3 秒后，Then 以向上滑出/滑入动画切换为下一条，循环播放
- Given 云函数 `cf-coupon-search` 查券成功（返回 code=0 且有优惠券），When 云函数执行完毕，Then 自动写入一条脱敏记录到 `bulletin_logs` 集合（字段规格见 PRD-07 §7.6.2）
- Given 弹幕组件读取数据，When 渲染时，Then 优先展示最近 2 小时内的真实事件（source=real），不足 5 条时用种子数据（source=seed）补足
- Given 弹幕展示的省钱金额，When 渲染，Then 必须是真实的"原价-券后价"差值，**严禁随机生成虚假金额**
- Given 弹幕组件，When 任何时候，Then **严禁出现"红包""免费领""中奖"等字样**（微信合规 5.11）
- Given B 端后台录入了种子弹幕，When 小程序读取 `bulletin_logs`，Then 种子数据与真实数据混合展示，用户无法区分

**弹幕文案模板（默认）：**
```
"{nickname}刚刚查券省了{amount}元"
"{nickname}成功找到{title}的隐藏券"
"{nickname}领到了{amount}元大额优惠券"
```

**脱敏昵称预设池（随机选取）：**
```
["省钱达人", "小*鼠用户", "精打细算", "羊毛党", "快乐小主妇", "购物达人", "淘宝小能手", "粉红小泡泡"]
```

### REQ-0104 查券使用提示（新手引导教程）

**描述：** 首次使用的用户展示极简 3 步引导图，教会用户"去淘宝复制链接 → 打开小栗鼠 → 领券"的完整流程，作为常驻的新手教育入口。

**验收标准：**
- Given 用户首次访问查券 Tab（本地无 `hasSeenGuide` 标记），When 页面渲染完成，Then 在搜索框下方展示可左右滑动的 3 步引导卡片
- Given 引导卡片正在展示，When 用户滑动至最后一步并点击"我知道了"，Then 引导卡片消失，设置 `hasSeenGuide = true` 持久化到本地存储
- Given 用户非首次访问（`hasSeenGuide = true`），When 页面渲染完成，Then 不展示引导卡片
- Given 用户想再次查看教程，When 在"我的"Tab 点击"使用教程"，Then 可重新查看引导内容（PRD-06）

### REQ-0105 搜索结果列表页

**描述：** 用户通过关键词搜索后，在查券 Tab 内展示的商品结果列表。采用单列卡片布局，强调价格对比和卷面额信息。

**卡片布局规格：**
```
┌──────────────────────────────────────┐
│  [商品图]  商品标题（最多2行）           │
│   90x90    券后价 ￥29.9   原价 ￥89.9      │
│            [则60元] Tag  已售 1.2万     │
└──────────────────────────────────────┘
```

**验收标准：**
- Given 关键词搜索返回结果，When 查券 Tab 内渲染，Then 搜索框保留在顶部（展示当前搜索关键词），下方展示单列商品卡片列表
- Given 每张商品卡片，When 渲染，Then 左侧展示商品缩略图（90x90px，圆角 8px），右侧展示：商品标题（2行）+ 券后价（主色大字）+ 原价（灰色删除线）+ 券面额 Tag + 销量
- Given 搜索结果超过 1 页，When 用户上拉至底部，Then 自动加载下一页（分页 page_size=20）
- Given 用户点击搜索框中的清除按钮，When 清除搜索内容，Then 恢复查券 Tab 默认首页状态
- Given 用户点击任意商品卡片，When 触发，Then 携带 tao_id 跳转商品详情页（PRD-02）

### REQ-0106 查券 Tab 默认首页布局

**描述：** 当用户没有搜索且剪贴板无内容时，查券 Tab 的默认展示状态。

**验收标准：**
- Given 用户打开查券 Tab 且无搜索行为，When 页面展示默认状态，Then 页面从上到下依次展示：
  - 实时查券成功弹幕组件（REQ-0103）
  - 巨型搜索输入框（REQ-0101，位于屏幕垂直方向 30%-40%）
  - 新手引导卡片（REQ-0104，仅首次访问）或“发现好价”推荐商品卡片（非首次访问，数据源复用 cf-feed-data（feed_type=hot_circle）前 3 条）
- Given 用户发起搜索，When 搜索结果返回，Then 默认首页内容被搜索结果列表替换（REQ-0105）

### REQ-0107 独立平台查券底层链路（淘券/京券查询）

**描述：** 明确分离淘宝与京东的查券底层逻辑。用户无需手动选择平台，系统通过正则自动路由至对应的折淘客转链 API（ZTK #1 或 #1.1）。

**验收标准：**
- Given 搜索输入（无论剪贴板还是手动），When 发起查询请求，Then 后端 `cf-coupon-search` 必须识别平台归属：淘宝口令/链接走 ZTK #1，京东链接走 ZTK #1.1。
- Given 返回结果，When 渲染展示，Then 商品标题前强制带上平台来源标签（`淘宝` 或 `京东`）。

## 1.5 边界与异常 (Edge Cases)

| 场景 | 系统行为 |
| :--- | :--- |
| **搜索结果为空（关键词搜索无匹配商品）** | 展示 Empty State 插画 + 文案"暂未找到相关优惠，换个关键词试试" + 搜索框保持可编辑状态 |
| **淘口令已过期或无效** | 展示提示"该链接已失效，请重新复制商品链接" + 搜索框保持可编辑状态 |
| **商品无优惠券（有商品但无券）** | 仍跳转详情页（PRD-02），详情页展示原价购买入口，但券区域显示"该商品暂无优惠券" |
| **用户快速连续点击搜索按钮** | 搜索按钮进入 loading 后禁用，防止重复请求 |
| **搜索框输入超长文本（>500字符）** | 前端截断至 500 字符，Toast 提示"输入内容过长" |
| **API 超时（>5秒）** | 参照 PRD-00 §0.4.4 容灾降级规范：展示骨架屏 + 友好文案 |
| **用户输入纯中文关键词（非链接）** | 触发关键词搜索流程，调用全网搜索 API 返回商品列表 |

## 1.6 非功能性需求 (Non-Functional Requirements)

| 类别 | 要求 |
| :--- | :--- |
| **性能** | 剪贴板读取 + 正则匹配 ≤ 200ms；搜索请求端到端响应 ≤ 3 秒 |
| **安全** | 剪贴板内容仅用于当次查询，不上传至任何服务器存储（隐私合规） |
| **兼容** | 支持微信 iOS/Android 最近 2 个大版本的基础库 |
| **可配置** | 弹幕文案模板、placeholder 文案可通过 B 端后台动态下发 |
