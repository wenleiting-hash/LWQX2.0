## 8.1 问题陈述 (Problem)

### 谁有这个问题？
平台运营者（你）。需要一个安全、高效的后台管理界面来完成以下高频操作：修改 API 秘钥、替换客服二维码、查看业务数据。

### 有多痛？
- 如果没有管理后台，每次更换 PID 或 AppKey 都需要修改小程序源代码 → 重新提交微信审核 → 等待 1-3 个工作日。在此期间如果原账号被封，业务完全停摆。
- 如果没有数据看板，运营者对"有多少人用、有多少人买、赚了多少钱"一无所知，无法做任何运营决策。

### 不做会怎样？
运营者成为"瞎子"——不知道业务状态，无法快速应对风控封号等突发事件。

## 8.3 用户旅程（运营者视角）(User Journey)

### 场景 A：紧急更换 PID（防封急救）

```
1. 运营者收到淘宝联盟通知：某个 PID 因违规被冻结
   → 登录 B 端管理台（Web 浏览器访问）

2. 进入"配置中心"页面
   → 找到"淘宝联盟 PID"配置项
   → 输入新的 PID 值
   → 点击 [保存]

3. 系统将新值写入云数据库 system_config 集合
   → 返回"保存成功"提示

4. 下一个用户在 C 端小程序发起查券请求时
   → 云函数读取到最新的 PID → 使用新 PID 生成转链
   → 佣金归属自动切换到新 PID，业务 0 中断
```

### 场景 B：查看今日业务概况

```
1. 运营者打开 B 端管理台，默认落地页为"数据看板"

2. 看板展示：
   - 今日 UV / 昨日 UV / 环比变化
   - 今日查券接口调用次数
   - 今日预估佣金（从折淘客订单接口拉取）
   - 转化漏斗图：打开→搜索→详情→复制口令

3. 运营者根据数据决策：
   - UV 下降 → 加大小红书投放
   - 转化率低 → 优化详情页文案
   - API 调用量异常高 → 检查是否被恶意刷接口
```

## 8.4 功能需求与验收标准 (Requirements)

### 模块一：API 参数集控中心 (P0 · Phase 1.0 MVP)

**1. 配置热更新**
- 管理员可实时修改 `ztk_appkey`, `taobao_pid`, `theme_color` 等核心参数。
- 表单包含明密文切换逻辑。

**2. 随机昵称池管理 (Nickname Pool)**
- **用途**：供晒单模块 (PRD-05) 匹配真实订单时使用。
- **功能**：SuperAdmin 可批量导入/编辑昵称数组（存储于 `system_config` 的 `nickname_pool` 字段）。

**3. 核心种子数据 (Seed Data)**
- **用途**：用于冷启动。
- **功能**：SuperAdmin 可直接操作 `bulletin_logs` 集合，预置高客单价的“假想”查券记录。

**验收标准：**
- Given 运营者进入配置中心页面，When 页面加载，Then 以表单形式展示所有配置项的当前值，敏感信息（AppKey/Secret）以 `****` 掩码展示，点击"显示"才可查看明文
- Given 运营者修改了 `taobao_pid` 的值，When 点击 [保存]，Then 系统将新值写入云数据库，返回"保存成功"Toast，页面展示更新后的值
- Given 运营者修改了 `theme_color`，When 保存成功，Then 页面提供色值预览（小色块展示），提示"C 端将在下次启动后生效"
- Given 运营者上传了新的客服二维码图片，When 点击 [上传]，Then 图片上传至云存储，URL 自动写入 `service_qrcode_url` 字段
- Given 运营者没有填写必填项（如 ztk_appkey 为空），When 点击保存，Then 表单校验失败，对应输入框标红提示"此项为必填"
- Given 运营者修改了公告配置并启用，When C 端用户下次 onLaunch，Then cf-get-config 返回最新公告 → 小程序弹窗展示

### 模块一(续)：晒单缓存管理（P0 · Phase 1.0 MVP）

**描述：** 晒单模块（PRD-05）Phase 1.0 的数据源为 `showcase_events_cache`（由云函数 `cf-sync-showcase` 每 5 分钟从折淘客订单库自动同步）。本模块提供缓存数据的监控与管理界面。

> ⚠️ `featured_orders` 集合**已降级为备用冷启动方案**，仅在自动同步无数据时手动补充种子商品。

**Schema 引用：** 见 PRD-07 §7.6.4 `showcase_events_cache` 集合设计

**功能项：**

| 功能 | 说明 |
| :--- | :--- |
| 缓存数据一览 | 表格展示 `showcase_events_cache` 中所有记录：脱敏昵称、商品标题、省钱金额、平台、event_timestamp |
| 同步状态监控 | 展示 `cf-sync-showcase` 最近一次执行时间、同步记录数，如超过 10 分钟未同步则显示红色告警 |
| 手动触发同步 | SuperAdmin 可点击 [立即同步] 按钮手动触发 `cf-sync-showcase` 云函数执行 |
| 过期清理 | 展示过期记录数（`event_timestamp` 超 48h），支持 [一键清理] 操作 |
| 种子数据补充 | 当缓存为空时（冷启动阶段），SuperAdmin 可手动录入种子晒单记录写入 `showcase_events_cache` |

**验收标准：**
- Given 运营者进入"晒单缓存管理"页面，When 页面加载，Then 展示 `showcase_events_cache` 集合中所有记录的列表（表格形式：脱敏昵称 + 商品标题 + 平台 Tag + 省钱金额 + 时间戳 + 操作按钮）
- Given 页面顶部同步状态区域，When 最近同步时间 ≤ 10 分钟前，Then 展示绿色状态"同步正常"；When 超过 10 分钟未同步，Then 展示红色告警"同步异常，请检查云函数"
- Given 运营者点击 [立即同步]，When 触发，Then 调用 `cf-sync-showcase` 云函数，返回同步结果（新增 N 条记录），刷新列表
- Given 运营者点击 [一键清理过期]，When 确认，Then 删除 `event_timestamp` 超过 48 小时的记录，返回"已清理 N 条"
- Given 缓存表为空（冷启动），When 运营者点击 [新增种子数据]，Then 弹出表单（商品标题、平台、原价、券后价），系统自动从 `nickname_pool` 随机分配昵称，写入 `showcase_events_cache`

### 模块一(续)：种子弹幕管理（P0 · Phase 1.0 MVP）

**描述：** 为查券页弹幕组件（PRD-01 REQ-0103）提供种子数据的录入管理。种子数据用于冷启动阶段当真实查券事件不足时充当塬底。

**Schema 引用：** 见 PRD-07 §7.6.2 `bulletin_logs` 集合设计（source=seed）

**验收标准：**
- Given 运营者进入"种子弹幕管理"页面，When 页面加载，Then 展示 `bulletin_logs` 集合中 `source=seed` 的所有记录列表
- Given 运营者点击 [新增种子弹幕]，When 弹出表单，Then 表单包含：脱敏昵称（可手动输入或从预设池选取）、省钱金额、商品标题（前6字）
- Given 运营者填写完成并保存，When 写入成功，Then 写入云数据库 `bulletin_logs` 集合，`source` 字段固定为 `seed`
- Given 运营者点击某条种子弹幕的 [删除]，When 确认后，Then 永久删除该条种子记录

### 模块二：数据看板（P1 · Phase 1.5）

**描述：** 运营者查看业务核心指标的可视化面板。

**看板指标：**

| 指标卡片 | 数据来源 | 展示格式 |
| :--- | :--- | :--- |
| 今日 UV | 小程序后台数据接口 或 自建埋点 | 数字 + 与昨日环比趋势箭头 |
| 查券调用次数 | 云函数调用日志统计 | 数字 + 折线趋势图（近7天） |
| 预估佣金 | 折淘客订单查询 API | 金额 + 与昨日对比 |
| 转化漏斗 | 前端埋点数据聚合 | 漏斗图：UV→搜索→详情→口令复制 |

**验收标准：**
- Given 运营者打开数据看板页面，When 页面加载，Then 展示 4 个核心指标卡片，每个卡片包含当前值 + 趋势指示
- Given 今日 UV 为 120，昨日 UV 为 100，When 环比计算，Then 展示 "↑ 20%" 绿色上升箭头
- Given 今日 UV 为 80，昨日 UV 为 100，When 环比计算，Then 展示 "↓ 20%" 红色下降箭头
- Given 数据源尚未接入（Phase 1.5 前），When 页面加载，Then 展示 mock 数据 + "数据接入中"标记

### 模块三：订单与佣金追踪（P1 · Phase 1.5）

**描述：** 桥接折淘客订单查询接口，展示跑单和佣金数据。

**验收标准：**
- Given 运营者进入订单追踪页面，When 页面加载，Then 展示订单列表表格（时间、商品名、订单金额、佣金比例、预估佣金、状态）
- Given 运营者选择日期范围筛选器，When 选择日期后点击查询，Then 列表按所选日期范围过滤
- Given 订单状态为"已结算"，When 渲染，Then 状态列展示绿色标签
- Given 订单状态为"待结算"，When 渲染，Then 状态列展示橙色标签

### 模块四：运营素材库（P2 · Phase 2.0 预留）

**描述：** 后台精选高佣商品，接入 AI 大模型自动生成营销文案。

**验收标准：**
- Given 运营者选择一款商品，When 点击 [AI 生成文案]，Then 系统将商品标题、价格、券面额等信息拼接为 prompt，调用豆包/Kimi API，返回一段适合小红书发布的种草文案
- Given AI 返回文案，When 展示，Then 提供 [复制] 和 [编辑] 按钮
- Given AI 接口超时或失败，When 等待 >10 秒，Then 展示"AI 暂时繁忙，请稍后重试"

## 8.5 边界与异常 (Edge Cases)

| 场景 | 系统行为 |
| :--- | :--- |
| **运营者未登录** | 跳转登录页面（用户名+密码基础认证） |
| **SuperAdmin 特权接入** | 账号 `role == 'SuperAdmin'` 时，解锁“一键重置配置”与“数据库 Collection 全读写”权限。该权限通过带 `secret_key` 的专用云函数实现。 |
| **云数据库写入失败** | 表单保持可编辑状态，Toast "保存失败，请检查网络后重试" |
| **上传的二维码图片过大（>2MB）** | 前端拦截，提示"图片大小不能超过2MB" |
| **浏览器兼容** | 支持 Chrome 最近 2 个大版本，其他浏览器不做适配保证 |

## 8.6 非功能性需求 (Non-Functional Requirements)

| 类别 | 要求 |
| :--- | :--- |
| **技术栈** | Vite + React 18 + TailwindCSS 4 + Radix UI + Ant Design（复用现有 `e:\WorkProject\XLS\admin` 项目基座） |
| **认证** | MVP 阶段使用简易用户名+密码登录，密码 bcrypt 加密存储 |
| **数据库** | 配置数据读写微信云数据库（通过云开发 HTTP API，见下方鉴权说明） |
| **响应式** | 仅适配桌面端（≥1024px 宽度），不需要移动端适配 |
| **部署** | 复用现有 Vite 部署方案（vite build → 静态托管/Nginx） |
| **云数据库 HTTP API 鉴权** | B 端服务通过微信云开发 HTTP API 读写云数据库，需通过 `appid + appsecret` 换取 `access_token`。Token 有效期 2 小时，B 端服务端需缓存并定时刷新，避免频繁请求。`appsecret` 存储在服务端 `.env` 文件中，严禁前端暴露 |
