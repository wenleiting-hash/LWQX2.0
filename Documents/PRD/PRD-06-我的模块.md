## 6.1 问题陈述 (Problem)

### 谁有这个问题？
已使用过查券功能的回头用户，以及需要联系客服或了解更多使用方法的新用户。

### 有多痛？
- 用户上次查过一款很心动的商品但没下单，现在想找回来却不知道在哪里看。
- 用户有问题想咨询运营者，但小程序内没有明确的联系入口。
- 如果运营者的微信号被封/换号，所有已发布的客服二维码全部失效。

### 不做会怎样？
用户回访时找不到之前的商品（流失）；运营者无法将用户沉淀到私域（无法持续触达）。

## 6.3 用户旅程 (User Journey)

```
1. 用户点击底部 Tab "我的"
   → 页面展示：头部用户信息区 + 功能列表

2. 用户信息区（轻量展示）
   → 初始展示微信默认头像 + "小栗鼠用户"固定文案
   → 引导用户一键获取头像和昵称（使用 `<button open-type="chooseAvatar">` + `<input type="nickname">` 机制），提升专属感

3. 功能列表
   ├── [📝 我的足迹] → 包含“浏览商品”与“收藏商品”双 Tab
   ├── [📖 使用教程] → 进入教程页面（图文引导）
   ├── [💬 联系我们] → 展示社群二维码、客服二维码、客服电话
   └── [❓ 常见问题] → 常见问题答疑列表页面

4a. 查券足迹流程
   → 用户点击 [查券足迹]
   → 进入历史记录列表页（按时间倒序排列）
   → 每条记录展示：商品缩略图 + 标题 + 券后价 + 查看时间
   → 点击任意记录 → 跳转详情页（PRD-02）

4b. 联系我们流程
   → 用户点击 [联系我们]
   → 弹出半屏浮层，提供三种联系方式：
     - 加入社群：展示社群群活码，长按识别
     - 专属客服：展示个人微信二维码，长按识别
     - 客服电话：点击一键拨号唤起手机拨号盘
   → 用户长按识别 → 跳转微信加好友流程
```

## 6.4 功能需求与验收标准 (Requirements)

### REQ-0601 我的足迹与收藏

**描述：** 记录用户在小程序内搜索过/浏览过的商品详情，以及主动收藏的商品，提供"找回"能力，防止用户流失。

**数据存储规格：**
- 存储位置：微信小程序本地存储（`wx.setStorageSync`）
- 存储结构：数组，每条记录含 `{ tao_id, title, image_url, price_after_coupon, original_price, timestamp, platform }`
- 存储上限：最多保留最近 100 条记录，超出后自动淘汰最早的记录（FIFO）

**验收标准：**
- Given 用户从任意入口进入商品详情页（PRD-02），When 详情页数据加载成功，Then 自动将该产品信息写入本地足迹存储（去重：同一 tao_id 只保留最新一次）
- Given 用户在详情页点击“收藏”，When 触发，Then 写入本地/云端收藏夹存储
- Given 用户进入“我的足迹”页面，When 页面加载，Then 顶部展示“浏览历史”和“我的收藏”双 Tab，默认展示“浏览历史”
- Given 足迹或收藏列表中的商品卡片，When 渲染，Then 展示：商品缩略图(60x60) + 标题(1行) + 券后价 + 时间
- Given 用户点击足迹/收藏中的商品，When 触发，Then 跳转商品详情页（PRD-02），重新请求最新数据
- Given 列表为空（从未查看/收藏过商品），When 页面加载，Then 展示 Empty State "暂无记录，快去查券吧"
- Given 用户想清空记录，When 点击页面右上角"清空"或"管理"按钮，Then 支持批量删除或一键清空

### REQ-0602 联系我们（社群/客服/电话）

**描述：** 提供多维度的联系方式，将用户沉淀到私域并提供售后保障。

**验收标准：**
- Given 用户点击 [联系我们]，When 触发，Then 弹出半屏浮层
- Given 浮层展示，When 渲染完成，Then 包含三个模块选项（通过云数据库实时控制各模块的开关和具体内容）：
  1. **加入社群**：展示群二维码，"长按识别二维码，加入专属福利群"
  2. **专属客服**：展示客服微信二维码，"长按添加福利官微信"
  3. **客服电话**：展示电话图标及号码，点击直接唤起系统拨号盘 `wx.makePhoneCall`
- Given 二维码图片加载失败，When 渲染，Then 展示文字 fallback（微信号或群号）

### REQ-0602.1 常见问题 (FAQ)

**描述：** 整理用户常见的问题列表，降低客服压力。

**验收标准：**
- Given 用户点击 [常见问题]，When 触发，Then 跳转至 FAQ 列表页
- Given 页面渲染，When 加载完成，Then 展示折叠面板（Accordion）形式的问题列表，点击问题展开解答文本。内容由云端获取。

### REQ-0603 使用教程回看

**描述：** 提供图文形式的查券使用教程，降低新手学习成本。

**验收标准：**
- Given 用户点击 [使用教程]，When 触发导航，Then 跳转至教程页面
- Given 教程页面，When 渲染，Then 展示与查券页新手引导（PRD-01 REQ-0104）相同的 3 步引导内容，但以完整图文长页面形式展示（非卡片轮播）
- Given 教程内容，When 展示，Then 包含以下步骤：
  - 步骤1：在淘宝/京东找到想买的商品，点击分享→复制链接（配操作截图）
  - 步骤2：打开微信，进入"小栗鼠"小程序（配小程序搜索截图）
  - 步骤3：自动弹出券信息，点击领券购买即可省钱（配查券成功截图）

## 6.5 边界与异常 (Edge Cases)

| 场景 | 系统行为 |
| :--- | :--- |
| **足迹商品已下架** | 点击后进入详情页，详情页展示"该商品已下架"（PRD-02 边界处理） |
| **本地存储被清除（用户清理微信缓存）** | 足迹丢失，展示空状态，不做恢复 |
| **客服微信被封/B端还未配置二维码** | 浮层展示文字 fallback，并提示"客服正在迁移中" |

## 6.6 非功能性需求 (Non-Functional Requirements)

| 类别 | 要求 |
| :--- | :--- |
| **存储** | 足迹数据存本地，不上云（隐私合规，减少云数据库开销） |
| **性能** | "我的"Tab 首屏加载 ≤ 1 秒（用户信息 + 功能列表为纯本地渲染；客服二维码数据取自 onLaunch 时 cf-get-config 的缓存结果，无额外网络请求） |
| **客服活码** | 二维码 URL 从小程序全局缓存中读取（源自 cf-get-config 返回的 `service_qrcode_url` 字段） |
| **埋点** | 足迹入口点击、足迹商品点击、教程入口点击、客服活码展示/识别 |
