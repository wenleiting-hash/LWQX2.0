## 4.1 问题陈述 (Problem)

### 谁有这个问题？
不知道买什么、但想"跟风抄作业"的用户。他们信任"大家都在买"的社会验证，倾向于选择已被市场验证的热销商品。

### 有多痛？
- 在淘宝/京东上看到的"热销榜"是平台付费推广的结果，用户对其真实性存疑。
- 用户缺乏一个基于真实销售数据、按时间维度分层的可信榜单。

### 不做会怎样？
丧失"无目的用户"的留存和转化机会。这类用户占下沉市场的主力。

## 4.2 成功指标 (Success Criteria)

| 指标 | 定义 | 目标值 |
| :--- | :--- | :---: |
| 榜单页日活占比 | 访问过榜单 Tab 的用户占总日活比例 | ≥ 15% |
| 榜单→详情页点击率 | 点击榜单商品进入详情的比例 | ≥ 20% |
| 人均浏览深度 | 用户在榜单页平均滚动浏览的商品数 | ≥ 10 个 |

---

## 4.3 用户旅程 (User Journey)

```
1. 用户点击底部 Tab "榜单"
   → 页面顶部展示统一品牌色的头部设计，不再受平台切换影响。
   → 紧接着下方展示“皇冠金刚区”（2行4列滑动或者8个常驻图标），包含：实时爆单榜、今日热销榜、实时人气、朋友圈热销、月度销售榜、超高优惠榜、超高销量榜、超高评分榜。

2. 默认选中 "🔥 实时爆单榜"
   → 在金刚区与列表之间，展示局部的平台切换控件（[淘宝榜单] / [京东榜单]）。
   → 列表式商品卡片，每卡片含：排名序号 + 商品图 + 标题 + 券后价 + 已售件数
   → 支持上拉加载更多

3. 用户点击金刚区内的其他图标（如 "📅 全天热卖" 或 "🏅 月度红榜"）
   → 瀑布流平滑切换数据源，列表重新加载

4. 用户点击任意商品卡片
   → 跳转详情页（PRD-02）
```

## 4.4 功能需求与验收标准 (Requirements)

### REQ-0401 榜单导航金刚区

**描述：** 榜单页顶部的导航区域，采用金刚区（Top Icon Grid）设计，容纳海量的榜单维度。

**金刚区配置：**

| 图标入口 | 淘宝数据源 | 京东数据源 |
| :--- | :--- | :--- |
| 🔥 实时爆单榜 | ZTK #17 实时2h | ZTK #18 实时2h |
| 📈 今日热销榜 | ZTK #24 全天销量 | ZTK #31 全天销量 |
| 🏆 实时人气 | ZTK #25 实时人气 | ZTK #32 实时人气 |
| 🌟 朋友圈热销 | ZTK #20 社交传播 | ZTK #27 社交传播 |
| 📅 月度销售榜 | ZTK #24 月度销量 | ZTK #31 月度销量 |
| 💸 超高优惠榜 | ZTK #21 高券面额 | ZTK #28 高券面额 |
| 📦 超高销量榜 | ZTK #22 高销量 | ZTK #29 高销量 |
| ⭐ 超高评分榜 | ZTK #23 高评分 | ZTK #30 高评分 |

**验收标准：**
- Given 用户进入榜单页，When 页面加载完成，Then 顶部展示金刚区图标组，默认选中"🔥 实时爆单榜"图标，下方展示对应数据
- Given 用户点击金刚区内其他图标，When 切换触发，Then 选中态样式切换（高亮指示当前榜单），下方列表展示切换后的数据源
- Given 金刚区切换请求已发起，When 等待响应，Then 展示列表骨架屏（3-5 个占位卡片），已有数据清空
- Given 用户快速来回切换，When 短时间内多次切换，Then 仅保留最后一次切换的请求，取消前序请求（防抖/竞态处理）

**状态管理规则：**
- 切换榜单时：**保留**用户当前选择的平台（淘宝/京东），切换后加载对应平台的新榜单数据
- 切换平台时：**保留**当前选中的榜单分类，仅切换数据源平台
- 分类 + 平台的组合状态在 Session 内缓存 5 分钟，切回已加载过的组合时直接展示缓存数据

### REQ-0402 榜单商品卡片

**描述：** 榜单页的商品展示卡片，与发现页的瀑布流卡片不同，采用单列横向布局，强调排名序号和销量数据。

**卡片布局规格：**
```
┌──────────────────────────────────────┐
│  ①   [商品图]  商品标题（最多2行）    │
│       60x60    券后价 ¥29.9           │
│                原价 ¥89.9  已售 1.2万  │
│                [券50元] Tag           │
└──────────────────────────────────────┘
```

**验收标准：**
- Given 商品列表数据返回，When 渲染卡片，Then 每张卡片左侧展示排名序号（1、2、3 使用品牌主色特殊样式，4+ 使用灰色普通样式）
- Given 商品销量数据，When 销量 ≥ 10000，Then 展示格式为"已售 1.2万"（保留1位小数）
- Given 商品销量数据，When 销量 < 10000，Then 展示精确数值"已售 8956"
- Given 列表首次加载，When 数据返回，Then 加载第 1 页（20条），支持上拉加载下一页
- Given 到达列表末尾，When 无更多数据，Then 展示"榜单到底啦~"

### REQ-0403 榜单数据局部平台切换

**描述：** 在榜单页金刚区下方，采用居中的胶囊形平台切换控件（淘宝榜单 / 京东榜单），只控制下方数据流来源，不影响页面头部主题色。

**验收标准：**
- Given 用户在"实时爆单榜"Tab 下，When 页面展示，Then 默认展示淘宝数据（ZTK #17），提供"淘宝榜单 | 京东榜单"平台切换按钮。
- Given 用户点击"京东榜单"，When 切换平台，Then 列表数据无缝切换为京东数据源（ZTK #18），保持相同的榜单维度。
- Given 用户触发平台切换，When 渲染，Then 页面头部的橙色品牌底色不会发生剧烈闪烁或改变。

## 4.5 边界与异常 (Edge Cases)

| 场景 | 系统行为 |
| :--- | :--- |
| **榜单数据为空** | 展示 Empty State "暂无榜单数据，稍后刷新试试" |
| **网络断连时切换 Tab** | Toast "网络不给力"，保留上一个 Tab 的缓存数据展示 |
| **API 返回数据与上次相同（未更新）** | 正常展示，不做特殊处理 |
| **下拉刷新** | 支持下拉刷新当前 Tab 的数据，从第 1 页重新加载 |

---

## 4.6 非功能性需求 (Non-Functional Requirements)

| 类别 | 要求 |
| :--- | :--- |
| **性能** | 首屏加载（第1页20条） ≤ 2 秒 |
| **缓存** | 每个 Tab + 平台维度的数据在 Session 内缓存 5 分钟，减少重复请求 |
| **埋点** | Tab 切换次数、平台切换次数、卡片点击（含排名位次）、分页加载深度 |
