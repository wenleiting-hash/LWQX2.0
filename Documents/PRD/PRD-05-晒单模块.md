## 5.1 问题陈述 (Problem)

### 谁有这个问题？
平台运营者（你）以及具有传播意愿的活跃用户。核心痛点是：没有一个低成本、高颜值的裂变工具，将小程序内的优惠信息向外部公域（小红书、朋友圈、微信群）扩散。

### 有多痛？
- 运营者每天需要手动截图、排版、加工产品信息来制作推广素材，效率极低。
- 用户即使发现了极大差价的商品，也没有便捷的方式"炫耀"和"分享"给朋友。
- 没有引流武器 = 没有新用户 = 首页和榜单都是死水。

### 不做会怎样？
产品无法获得自然增长流量。所有用户都依赖运营者的纯人力投放，天花板极低。

| 指标 | 定义 | 目标值 |

| 晒单页日均 PV | 晒单 Tab 的每日页面浏览量 | ≥ 日活的 20% |

## 5.3 用户旅程 (User Journey)

### 场景 A：运营者/用户浏览实时晒单

```
1. 用户点击底部导航 "晒单" Tab
   → 页面加载：触发最新订单检索逻辑
   → 交互反馈：若 10 分钟内有新成交，在屏幕顶部弹出轻提示："为您发现 3 条最新晒单"

2. 用户浏览瀑布流
   → 瀑布流数据源：云数据库 showcase_events_cache（已预处理的实时晒单缓存表）
   → 用户身份展示：直接读取缓存表中的脱敏昵称字段（如 "省钱达人"、"用户*9527"）
   
3. 用户点击感兴趣的爆款商品
   → 跳转至商品详情页（PRD-02）
   → 详情页展示该商品的实时优惠券与省钱金额

4. 转化路径
   → 用户点击 [生成海报] 或 [一键领券]
   → 完成裂变或购买，产生新的真实订单记录，循环至晒单池
```

## 5.4 功能需求与验收标准 (Requirements)

### REQ-0500 顶部实时脱敏轮播播报（下单提醒）

**描述：** 在晒单页顶部（瀑布流上方）放置与查券首页类似的实时播报轮播（Swiper），动态展示“刚刚 XXX 成功省钱下单”的文字滚动信息，烘托热卖氛围。

**验收标准：**
- Given 用户进入晒单页，When 页面渲染，Then 顶部展示 1 行高度的自动垂直翻滚轮播。
- Given 播报数据，When 读取，Then 与首页查券成功的播报数据源一致，复用脱敏规则。
- Given 用户浏览，When 轮播持续播放，Then 严禁出现可点击交互（防止打断浏览瀑布流体验）。

### REQ-0501 真实订单双列图文瀑布流

**描述：** 晒单页的核心内容区域，通过展示真实的电商交易日志制造热闹的“薅羊毛”氛围。

**数据源与身份逻辑：**
- **核心数据源**：云数据库 `showcase_events_cache` 集合（实时晒单缓存表，Schema 见 PRD-07 §7.6.4）。该表由云函数 `cf-sync-showcase` 每 5 分钟从原始订单库同步并预处理。
- **用户信息匹配**：直接读取缓存表中已预处理好的 `nickname_masked` 字段（如：“小*鼠用户”、“省钱专家”、“羊毛队长”），前端无需二次计算。
- **平台来源标识**：根据 `platform` 字段，在卡片商品标题前展示微型灰底 Tag（“淘宝”或“京东”），样式与 PRD-02 REQ-0201 统一（背景 `#F5F5F5`，文字 `#666`）。
- **排序策略**：优先展示最近一小时进入缓存的记录 → 其次按 `saved_amount` 降序排列。

**REQ-0501-A 进场实时提示：**
- **逻辑**：用户进入晒单 Tab 时，查询 `showcase_events_cache` 中 `event_timestamp` 在最近 10 分钟内的记录数。
- **UI**：若记录数 ≥ 1，在页面顶端弹出“提示条组件”，展示文案如：“刚刚有 5 位用户下单省钱，点击查看”。

**卡片布局规格：**
```
┌───────────────┐
│  [商品主图]     │  ← 1:1 比例，圆角 8px
│               │
├───────────────┤
│ [淘宝] Tag     │  ← 灰底微型平台标识
│ {随机脱敏昵称} │  ← nickname_masked 字段
│ 刚刚下单了...  │
│               │
│ ¥39.9  券后价  │  ← #FF5500 加粗
│ 已省 ¥150 元   │  ← 强调真实省钱数额
└───────────────┘
```

**验收标准：**
- Given 晒单页加载完成，When 渲染瀑布流，Then 展示双列交错卡片，布局规范与发现页一致（PRD-03 REQ-0302）
- Given 每张卡片，When 渲染，Then 除标准产品信息外，额外展示"省XX元"的红色 Tag（省钱金额 = 原价 - 券后价）
- Given 省钱金额 ≤ 0（无优惠券或券后价 ≥ 原价），When 渲染，Then 不展示"省XX元"Tag
- Given 用户点击商品卡片图片或标题区域，When 触发，Then 跳转详情页（PRD-02），携带商品 ID
- Given 用户上拉至底部，When 触发加载，Then 自动请求下一页数据，追加到列表

### REQ-0502 一键生成海报（复用 PRD-02 Canvas 组件）

**描述：** 晒单页通过详情页（PRD-02 REQ-0203）的海报生成器实现裂变能力。用户点击晒单页的商品卡片后，进入详情页，在详情页底部点击 [生成海报]。

**验收标准：**
- 复用 PRD-02 REQ-0203 的全部验收标准，无需重复开发
- Given 用户从晒单页进入详情页，When 海报生成成功并保存，Then 用户可通过系统返回键回到晒单页，滚动位置保持不变

### REQ-0503 快速下领券入口（列表页快捷操作）

**描述：** 为了缩短交易链路，在晒单瀑布流卡片中直接提供“一键领券”的悬浮或底部按钮操作，用户无需进入详情页即可唤起复制淘口令的弹层。

**验收标准：**
- Given 晒单商品卡片渲染，When 有有效优惠券存在，Then 在卡片右下角展示鲜艳（如主色 #FF6200）的 [领券抢购] 按钮。
- Given 用户点击卡片上的 [领券抢购]，When 触发交互，Then 直接在当前页面底部弹起与 PRD-02 REQ-0202 一致的半屏转链成功/复制弹层。
- Given 用户点击卡片非按钮区域（如商品图或标题），When 触发，Then 跳转详情页（PRD-02），展现完整信息。

## 5.5 边界与异常 (Edge Cases)

| 场景 | 系统行为 |
| :--- | :--- |
| **瀑布流首次加载失败** | 展示 Empty State + "加载失败，点击重试" |
| **所有商品均无优惠券** | 正常展示，但不展示"省XX元"Tag |
| **用户未安装淘宝/京东 APP** | 复制口令后弹窗提示"请先安装淘宝/京东 APP" |

### 微信合规专项（5.1.3 诱导分享朋友圈）

| 合规风险点 | 强制规避措施 |
| :--- | :--- |
| 海报按钮文案 | 仅使用"生成海报"或"保存图片"，**严禁**"分享到朋友圈"/"转发领券" |
| 海报内容 | **严禁**包含"分享给好友得红包""转发领优惠"等利益诱导文案 |
| 保存按钮特效 | **禁止**使用红点提醒、呼吸灯、抖动等诱导性动效 |

## 5.6 非功能性需求 (Non-Functional Requirements)

| 类别 | 要求 |
| :--- | :--- |
| **性能** | 首屏加载 ≤ 2 秒 |
| **数据实时性** | 订单数据建议每 5 分钟通过云函数同步一次，确保“刚刚”文案的准确性 |
| **用户体验** | 随机匹配的昵称应具备多样性，避免连续 3 个卡片出现相同昵称 |
| **埋点** | Tab 点击进入、新单提示条展示/点击、卡片点击跳转详情 |
