# 📋 小栗鼠 (Little Squirrel) 3.0 项目需求评审报告

**日期：** 2026-04-20
**状态：** 最终评审中 (Final Review)
**主导：** PM, Architect, SuperAdmin

---

## 1. 评审背景与目标
本次评审针对“小栗鼠”纯导购小程序的 9 份模块化 PRD (PRD-00 至 PRD-08) 进行系统性合规、技术可行性及业务逻辑对齐。目标是确保在进入研发阶段前，所有业务边界清晰，没有任何由于接口限制或合规红线导致的架构性风险。

---

## 2. 核心业务模式盘点 (Business Essence)
产品定位为 **“极致轻量、极简画风、纯粹工具”** 的导购平台。
- **盈利模式**：全量获取折淘客 CPS 佣金，不与 C 端用户分成，降低财务风险与合规成本。
- **引流核心**：剪贴板自动识别（淘口令/京东链接） + 实时省钱弹幕。
- **裂变工具**：基于 Canvas 2D 的高颜值商品海报，主攻小红书与朋友圈。

---

## 3. 技术架构与安全共识 (Technical Consensus)
| 维度 | 决策方案 | 理由 |
| :--- | :--- | :--- |
| **前端选型** | 微信原生小程序 (WXML/WXSS) | 追求冷启动速度与原生交互体验，拒绝编译框架。 |
| **后端选型** | 微信云开发 (Cloud Base) | 零服务器维护、免域名备选、天然安全域名白名单。 |
| **安全策略** | **前端零秘钥原则** | 所有 AppKey/PID 严禁入包。所有 API 请求经由云函数在腾讯内网发起。 |
| **数据热更新** | `system_config` 驱动 | PID、主题色、公告等均存储于云数据库，B 端修改后 C 端实时生效。 |

---

## 4. 重点模块评审修正 (Key Revisions)

### 4.1 晒单模块 (PRD-05) - 真实感氛围重构
- **数据源**：由手动录入改为 **折淘客订单查询接口实时驱动**。
- **身份脱敏**：针对接口无用户信息的问题，采用 **“真实单号 + 随机脱敏昵称池”** 的组合方案。
- **进场快讯**：用户进入 Tab 触发 10 分钟内新单检索，顶部弹出“最新播报提示条”。

### 4.2 管理后台 (PRD-08) - 权限等级制度
- **SuperAdmin 权限**：明确 SuperAdmin 具有最高特权，可绕过 API 限制直接通过专用接口读写云数据库 Collection。
- **配置管控**：提供“随机昵称池”和“种子弹幕”维护界面，平衡冷启动数据与真实数据。

---

## 5. 合规性审查 (Compliance Check)
依据《微信小程序运营规范》，针对 5.x 章节进行专项对齐：
- **5.1.3 (诱导分享)**：海报保存按钮仅使用“保存图片”，绝无利益诱导，无强制分享回调校验。
- **5.16 (骚扰用户)**：剪贴板弹窗每 Session 仅触发一次，且支持用户主动关闭。
- **5.11 (欺诈/虚假)**：弹幕文案严禁使用“中奖”“红包”字样，仅展示真实的“已省”或“领券”。

## 6. 评审决议记录 (Finalized Decisions)

### Q1. 订单同步频率与成本 → ✅ 已决议
**决议**：引入 `showcase_events_cache` 实时晒单缓存表（Schema 见 PRD-07 §7.6.4）。云函数 `cf-sync-showcase` 每 5 分钟从原始订单库同步并完成昵称匹配，写入缓存表。C 端晒单页直接读取缓存表，避免频繁扫描原始订单库。缓存表仅保留 48 小时数据，过期自动清理。

### Q2. 京东与淘宝的 UI 识别度 → ✅ 已决议
**决议**：**保持栗橙色 (#FF5500) 主色调不变**。仅通过商品标题前的微型灰底 Tag（"淘宝"或"京东"）区分来源，Tag 样式统一为背景 `#F5F5F5`、文字 `#666`，不引入平台品牌色。已同步更新 PRD-02 REQ-0201 与 PRD-05 REQ-0501。

### Q3. B 端安全登录方案 → ✅ 已决议
**决议**：**保持现有账号+密码认证方式**，不引入微信扫码登录。MVP 阶段 SuperAdmin 通过专用高权云函数（带 `secret_key`）操作数据库，安全性由密钥管控而非登录方式。
